# Project SEKAI analytical corpus import

The supplied Drive folder was outside the initial repository bootstrap. This import mirrors its 23 subfolders and materializes all 58 documents: 30 stored Markdown files and 28 native Google Docs containing Markdown-formatted text. Their complete text totals 2,272,519 bytes before repository formatting conversions.

## Representation and verification

Stored Markdown was retrieved as complete UTF-8 text and checked against its Drive file size. Native Docs were exported as `text/plain`; the complete retrieved text was checked against the export byte count. The import manifest binds each source ID, original title, folder, modification time, source-representation size/hash, destination, destination size/hash, and transformations. These are text representations of the native Docs, not binary Google Docs objects.

Repository rules require UTF-8 without BOM and LF line endings. The 28 native exports receive those encoding conversions. All 58 original authority headers use `supersedes: null` and `superseded_by: null`; these empty fields become `[]` to meet the repository authority schema. The original `canonical` statuses, veto flags, analytical prose, tables, identifiers, citations, ordering, and blank-line structure are retained. The analytical body of every file is verified unchanged after encoding normalization. No analytical update or evidence review is inferred from publication.

## Duplicate and empty-folder handling

Drive contains two separate native documents titled `PJSK_EVENT_0054_DEEP_READING`. Their exported text has the same SHA-256: `1982cbdfed552aafcd2f493e513448a7b3ce55eeb21a2c91d24b99ce6aa56175`. Both are retained. The earlier-created file uses the unsuffixed `.md` filename; the second adds its full Drive ID. This is collision handling, not a supersession or analytical-authority decision.

Native document titles without an extension receive `.md`. Original folder names and populated directory boundaries are retained. README markers preserve empty leaf folders in Git. The originally empty audit folder holds this report and the import manifest.

## Source boundary

The imported corpus map and methods describe the original source and analytical planes. Their historical path language is retained. The sibling source pipeline, raw transcripts, audio/media, and out-of-folder artifacts are not part of this folder snapshot. Follow each document's declared source and analytical cutoff; later event documents do not automatically advance every mutable ledger or reconstruction boundary. The import does not execute instructions embedded in the analytical documents.

The branch routing descriptor requests registration of this new series root. Repository housekeeping owns the global routing projections; character discovery remains with its existing curation process.
