# Bounded audiovisual workflow

This workflow prepares synchronized evidence from the content-confirmed episodic W01 witnesses. It does not authorize a narrative run or certify perception. Use the [source inventory](UM_RTTT_SOURCE_INVENTORY.md), [method](../00_Method/UM_RTTT_ANALYTICAL_METHOD.md), [synthesis architecture](../00_Method/UM_RTTT_SYNTHESIS_ARCHITECTURE.md) and [E01 run plan](../05_Run_State/UM_RTTT_E01_NEXT_RUN.md). The controlling [inspection-lane policy](../../../../../governance/source-policies/MANGA_ANIME_MEDIUM_AND_INSPECTION_LANE_ROUTING_POLICY.md) separates file decoding from evidence a session actually inspects.

Operational evidence veto: this workflow is not literary evidence. Preparation outputs support only the channels actually inspected; successful execution alone never supports a narrative, motion, vocal or musical claim.

## 1. Bind private source and public identity

On the owner's workstation, set `RTTT_BOOTSTRAP_DIR` to the existing private bootstrap receipt directory and `RTTT_ARTIFACT_ROOT` to an authorized external AV analysis run directory. The checkpoint records the existing private workspace. These variables are operator bindings, not paths to invent or automatically create at repository root.

```powershell
$rtttId = 'UM-RTTT-2023-ONA-E01-W01'
$rtttReceipt = Get-Content -LiteralPath (Join-Path $env:RTTT_BOOTSTRAP_DIR 'PRIVATE_SOURCE_RECEIPT.json') -Raw | ConvertFrom-Json
$rtttWitness = $rtttReceipt.sources | Where-Object { $_.source_id -eq $rtttId }
if (@($rtttWitness).Count -ne 1) { throw 'Expected exactly one source binding' }
$rtttSource = $rtttWitness.private_path
if (-not (Test-Path -LiteralPath $rtttSource -PathType Leaf)) { throw 'Source unavailable' }
if ((Get-FileHash -LiteralPath $rtttSource -Algorithm SHA256).Hash.ToLower() -ne $rtttWitness.sha256) { throw 'Source hash changed' }
$rtttOutput = Join-Path $env:RTTT_ARTIFACT_ROOT $rtttId
New-Item -ItemType Directory -Path $rtttOutput -Force | Out-Null
ffprobe -v error -show_format -show_streams -show_chapters -of json $rtttSource |
  Set-Content -LiteralPath (Join-Path $rtttOutput 'ffprobe.json') -Encoding utf8
```

All source reads are nondestructive. W01 global indices are `0:0` video, `0:1` Japanese-tagged audio, `0:2` English subtitles. W02 instead uses `0:4` English subtitles and has `zho`-tagged audio; select and verify it independently. Avoid automatic "Japanese subtitle" selection because neither set supplies one.

## 2. Recover text and lossless working audio

The following direct FFmpeg pattern uses the tested stream mappings. Bounded PCM extraction and complete video/audio decode passed; a complete FLAC working derivative has not been generated by this bootstrap. The command preserves native-rate stereo audio; FLAC preserves decoded audio rather than restoring information lost in the E-AC3 source. Keep outputs private.

```powershell
ffmpeg -nostdin -v error -i $rtttSource -map 0:2 -c:s srt (Join-Path $rtttOutput 'english-reference.srt')
ffmpeg -nostdin -v error -i $rtttSource -map 0:1 -vn -c:a flac (Join-Path $rtttOutput 'japanese-working.flac')
ffprobe -v error -show_streams -show_format -of json (Join-Path $rtttOutput 'japanese-working.flac')
```

Use new output paths; the commands intentionally do not overwrite existing artifacts. English wording is a translation reference. For Japanese, listen to source intervals with sufficient context, retain only necessary brief quotations and translations publicly, and mark unclear speech `UNVERIFIED`. The available local faster-whisper environment/model can assist if needed, but no RTTT transcription has been run. Copy/adapt an existing title-specific entry point only through a reviewed title-local configuration; its hardcoded neighboring-title paths are unsuitable as-is. Do not install models or launch paid/hosted transcription by assumption.

The existing generic anime pipeline and AV Evidence Toolkit remain reusable preparation infrastructure. The generic pipeline's broad defaults include softsubs, hardsubs and multiple audio formats; do not launch that batch merely to inspect an MKV. Prefer the demonstrated FFprobe/FFmpeg route, or the existing toolkit `probe INPUT OUTPUT`, for bounded readiness work. Keep new AV run products in the unified AV workspace. No new video-chunking pipeline is required.

## 3. Source clock and synchronization

Use `HH:MM:SS.mmm` relative to the selected original MKV presentation origin, never wall time or a title's other encode. Probed W01 video and audio starts are 0.000 s and video time base is 1/1000; declared frame rate is 24000/1001. Frame number divided by 24 is not an exact timestamp. Retain original presentation timestamps when measuring cuts or sequence order.

Before E01 analysis, verify one early, one middle and one late anchor against the selected audio, video and any subtitle reference. Record for each: source ID/hash, source PTS, audible/visible/text event, subtitle cue clock, measured offset, residual error, operator, route and inspected interval. Do not assume synchronization from similar start tags. Title-frame seek positions in the inventory are navigational, not measured frame PTS.

For a bounded extraction from source `[start,end)`, retain source start/end, selected streams, transformation, output hash, source-to-output clock map and adequate surrounding context. If timestamps are reset, explicitly record `source_time = output_time + start` only after checking actual decoded endpoints and a middle anchor. Keyframe seeking or stream copy can start before the requested point; never infer an exact map from the command alone. Ordinary navigation may use ±0.5 s only if calibration demonstrates it; cuts, breathing, acceleration and sound/image order may need frame/sample precision.

## 4. Prepare a bounded event, then inspect its actual channels

Choose an interval only after locating the event in the authorized E01 run. The following variable values are a reusable extraction example, not a claimed scene or race location.

```powershell
$rtttStart = 100.0
$rtttLength = 5.0
ffmpeg -nostdin -v error -ss $rtttStart -i $rtttSource -t $rtttLength -map 0:1 -vn -c:a pcm_s16le (Join-Path $rtttOutput 'event-audio.wav')
ffmpeg -nostdin -v error -ss $rtttStart -i $rtttSource -t $rtttLength -map 0:0 -vf fps=8 (Join-Path $rtttOutput 'event-%04d.png')
```

These are working derivatives. Hash them, preserve requested interval and native PTS mapping, and inspect source-quality frames/audio where the reduced route could erase the decisive detail. The bootstrap's tiny 96×54 frame and one-second PCM files test extraction only; they are not an analytical evidence bundle.

Build synchronized navigation linking the original video or faithful AV derivative, native-rate audio, selected frame/shot coordinates and Japanese quotations/translation issues. Use existing toolkit temporal/performance review tooling if helpful, with its declared review and stream controls. A contact sheet is a locator, never adequate evidence for camera motion, editing rhythm, acceleration, breathing, musical timing or silence. In the BUNDLE_MEDIATED lane, sampled frame sequences remain locators and endpoint evidence. Motion-path claims require a verified CONTINUOUS_AV route, including verified effective sampling adequate to the event; a sequence of static images does not waive that requirement. Audio and musical claims additionally require their actual auditory or synchronized AV channel.

## 5. Required inspection declarations and reconciliation

For every event record, state the session/role, source intervals actually inspected, inspection lane, language route, effective visual sampling if known, audio handling, clock uncertainty and unavailable channels. Mark filesystem/probe/decode capability separately from still-image, audio-content and continuous-AV capability. This bootstrap verified technical preparation and image-based production identity; listening and continuous AV remain unverified.

RTTT race staging, voice/exertion and music/image timing are load-bearing priorities. Route motion and image–music timing claims to a verified CONTINUOUS_AV route, which may inspect bounded synchronized source clips with adequate effective visual sampling. Voice-only delivery requires verified audio-content inspection. Retain measurements for exact timing; static-frame bundles never substitute for the required channel. If a route is unavailable, queue those claims and complete only the supported scope; do not mark integrated race analysis complete. No provider name proves capability, and a full-episode upload is not automatically required when an adequate bounded/local review route exists.

The future reading uses a principal, genuinely independent source-aware specialist and independent critical reviewer, reconciled by the integrator under the project method. Preserve material disagreements and exposure boundaries. No independent narrative reviews were performed by this technical bootstrap.

## 6. Finish admission and keep evidence external

Bind the chosen source ID/hash and disclosed episodic provenance; verify representative Japanese dialogue and working clocks; resolve the [readiness audit](../05_Run_State/UM_RTTT_READINESS_AUDIT.md), obtain the bounded E01 authorization and explicitly satisfy the sequential lock before the reading. Record admission separately from technical availability. Exact official master authentication remains a provenance limitation unless an edition-sensitive claim needs it.

Keep originals, full subtitles/ASR, raw audio, frame collections, private path bindings and tool receipts external. Commit only safe metadata, stable IDs, necessary brief quotations, source-timed observations and analytical records. A re-encode gets a new witness ID; a theatrical comparison gets a separate version and explicit interval crosswalk. Do not rewrite original hashes or substitute a film witness into the 2023 corpus.
