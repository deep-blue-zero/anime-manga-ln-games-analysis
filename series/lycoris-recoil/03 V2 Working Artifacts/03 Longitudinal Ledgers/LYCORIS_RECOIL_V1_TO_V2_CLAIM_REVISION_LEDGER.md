# Lycoris Recoil V1 → V2 Claim Revision Ledger

## 1. Responsibility

This ledger preserves the transition from prior-generation V1 interpretations to current V2 authority.

It exists so that V2 can revise earlier work without either:

- silently rewriting V1;
- or defending V1 merely for consistency.

Allowed formal transitions:

- `PRESERVE`
- `STRENGTHEN`
- `REVISE`
- `DOWNGRADE`
- `REJECT`
- `OPEN`

---

# 2. Prospective contamination rule

**Do not preload detailed V1 claims into the E01 prospective pass.**

For each episode:

1. perform source-native V2 passes first;
2. formulate V2 findings;
3. only then consult V1 where a claim-domain comparison is useful;
4. add a revision record after the V2 evidence exists.

This ordering prevents V1 from becoming the answer key for the prospective reread.

# 6. Transition semantics

## `PRESERVE`

V2 independently supports the substance of the V1 claim without material scope change.

## `STRENGTHEN`

V2 supplies materially better or broader evidence for the same core formulation.

## `REVISE`

The central idea survives but its formulation, conditions, or causal explanation materially changes.

## `DOWNGRADE`

The claim remains possible but V1 expressed more certainty or scope than V2 supports.

## `REJECT`

V2 evidence contradicts the claim sufficiently that it should no longer be used as current authority.

## `OPEN`

The claim remains unresolved at the current V2 boundary.

---

# 7. Revision discipline

Do not:

- use a later V2 outcome to rewrite the wording of V1;
- classify a claim as `PRESERVE` merely because V1 sounds plausible;
- treat absence of contradiction as confirmation;
- downgrade only because a later source is different without checking state/conditions;
- allow derivative sources alone to reject high-confidence A1 findings.
