# Checkpoint and integration ledger

## Responsibility

This register prevents source closure, ledger synchronization, synthesis readiness and reconstruction acceptance from collapsing into one “done” state. No analytical checkpoint, run, release or accepted source frontier exists at INITIAL. A bootstrap schema is not an authorization receipt.

## Operational schemas

| Register / ID | Required fields |
|---|---|
| Unit transaction `AP-TX-nnnn` | Authorized run/operation; witness and exact unit; entering/exit frontier; full reading path; component coverage; evidence/claim/serial/character/register changes or scoped no-change findings; retrieval and modality debt; reviewer; disposition; next authorized operation or NONE |
| Checkpoint freeze `AP-CP-nn` | Selected admitted boundary; exact input file set/digests and authority; preserved prospective claims/predictions; chronology and knowledge states; full reconciliation report; contradictions; role gaps; remaining source and inspection debts; release limits |
| Dependency `AP-DEP-nnnn` | Upstream witness/evidence/claim/version; downstream state/study/model/synthesis; change trigger; required review; owner; OPEN/RESOLVED_WITH_ROUTE/ACCEPTED_LIMITATION; resolution evidence |
| Role-gap `AP-RG-nnnn` | Required analytical responsibility; observed coverage; missing situations/relationships/language/forms; effect on synthesis; targeted evidence return or specialist; owner and completion criterion |
| Handoff `AP-HO-nnnn` | Base snapshot; full input/output paths/digests; witness/admission/knowledge boundary; authority generation; assigned responsibility; owners; complete transfer receipt; returned changes/limits; base-candidate-current drift result; acceptance and unresolved dependencies |
| Gate review `AP-GR-nnnn` | Architecture gate G0–G12; evidence examined; independent reviewer when required; deficiencies; pass/hold/bounded acceptance; exact accepted boundary; next permitted action |

The scope of a no-change finding is explicit. Missing ledger rows, missing images or untested locators cannot be silently treated as “no change” or “not applicable.” Handoff fields are filled only from actual observed values; unknown model settings, hashes, authorization or review outcomes remain unknown.

## Closeout and preservation

Future closeout accepts the complete reading and synchronized registers atomically. Verify source identity and full-component coverage; retrieve central evidence; inspect strong counterreadings and ordinary-life controls; confirm no prospective leakage; verify the exact allowed next operation. If any mandatory piece is absent, leave the transaction open with a precise owner and resume instruction.

At a checkpoint, preserve full readings and a frozen claim/state view, not just a narrative summary. Establish role gaps and their effect before commissioning monographs or specialists. Later interpretive changes use the claim ledger. Frozen bytes and historic knowledge boundaries remain recoverable.

A cross-session handoff follows the [full-output contract](../../governance/source-policies/MANGA_ANIME_ANALYTICAL_HANDOFF_AND_INTEGRATION_CONTRACT.md). The receiver reads the full governing and analytical inputs. A returning draft includes complete files and change/evidence routes. The integrator compares the handed-off base, returned candidate and current target before acceptance; branch movement is a reason for reconciliation, never blind replacement or loss of prior argument.
