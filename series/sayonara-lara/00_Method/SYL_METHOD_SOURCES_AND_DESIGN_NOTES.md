## 3. Documented tooling references

These are source links for tooling choices, not records of installations or successful runtime probes. A newer documentation page or installed version may change the exact API. Pin versions after testing the chosen environment. Model downloads, endpoint access, cost, account permission, and service terms remain separate checks.

<a id="t01"></a>
### T01. FFprobe

[Official FFprobe documentation](https://ffmpeg.org/ffprobe.html)

Use for stream, codec, timing, language-tag, and container inspection. Metadata identifies a candidate track; it does not certify the spoken language, speaker, or model inspection of content.

<a id="t02"></a>
### T02. FFmpeg filters

[Official FFmpeg filter documentation](https://ffmpeg.org/ffmpeg-filters.html)

Use signal filters only for bounded questions and retain the source-to-derivative mapping. A threshold-based silence detector reports behavior under its configured threshold, not a semantic absence of meaningful sound. The protocol's extraction recipes are illustrative and were not executed on the anime here.

<a id="t03"></a>
### T03. faster-whisper

[Maintainer repository and usage documentation](https://github.com/SYSTRAN/faster-whisper)

The documented interface supports local model directories, language selection, voice-activity filtering, and word-timestamp options. The returned segments must actually be consumed to execute the lazy transcription. Choose a multilingual Japanese-capable model, verify the installed version, and test the relevant material. Package installation is not model-weight availability; using a remote model name can trigger downloading.

<a id="t04"></a>
### T04. WhisperX

[Maintainer repository and limitations](https://github.com/m-bain/whisperX)

A potential helper for alignment and diarization integration, not a replacement for source verification. Language-compatible alignment resources and overlap behavior need actual checking. The documentation warns about overlapping speech and imperfect diarization. Do not assume a particular Japanese aligner exists or works in the current installation.

<a id="t05"></a>
### T05. Parselmouth / Praat

[Parselmouth documentation](https://parselmouth.readthedocs.io/en/stable/)

A Python interface to Praat functionality for reproducible acoustic measurements. Parameter choice, mixed sound, segmentation, and pitch-tracking failure matter. Measurements describe the measured signal; interpreting a performed personality is a separate evidence-grounded step.

<a id="t06"></a>
### T06. pyannote community diarization

[Official community model card](https://huggingface.co/pyannote/speaker-diarization-community-1)

A conditional speaker-segmentation option with access conditions. It can run locally after appropriate acquisition, but anonymous speaker clusters still require attribution. The documented preprocessing includes channel/rate transformations; retain the original mix and do not use this derivative for spatial claims.

<a id="t07"></a>
### T07. OpenAI audio-input chat

[Official audio Chat Completions guide](https://developers.openai.com/api/docs/guides/audio-chat-completions)

The inspected guide gives `gpt-audio-1.5` as an audio-input example. This establishes a documented route to investigate, not evidence that a specific Chat, Work, or Codex session receives audio samples. Verify the exact current endpoint and schema, then use a task-specific capability probe. A native-audio model's interpretive output remains fallible and must be linked to what it actually inspected.

<a id="t08"></a>
### T08. OpenAI transcription

[Official transcription guide](https://developers.openai.com/api/docs/guides/transcription)

Speech-to-text is a distinct task and output from a performed-voice review. A transcript may assist wording or alignment; it cannot independently establish timbre, emotional inflection, or a sound-image relationship. Do not infer API entitlement or spending authorization from a Chat subscription.
