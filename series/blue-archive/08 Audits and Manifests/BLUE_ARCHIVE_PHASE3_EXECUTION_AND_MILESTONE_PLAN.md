The [Phase 3 scope/readiness audit](BLUE_ARCHIVE_PHASE3_FULL_CAST_SCOPE_AND_READINESS_AUDIT.md) must reconcile the following candidate responsibilities:

- actual character, directed relationship, ensemble and institutional questions represented by the 12 MAIN arc accounts, 61 EVENT packages, 65 GROUP objects and 32 MINI objects.

These populations overlap and are not additive person counts. In particular, 148 families are not 148 certified unique biographies; 540 assessed routes are not an exhaustive cast census; 27 objects do not create 27 invented people. Alias, variant, counterpart, named/local-role and collective distinctions must be adjudicated with positive evidence. Secure existing global character identities may be reused; this work does not create or edit global curation records.

Each candidate requires a traceable disposition: independent character monograph, directed relationship/ensemble package, institutional package, represented inside another named package, or an evidence-specific deferral with a revisit trigger. `REVIEW_PENDING` means unfinished required adjudication, not ineligibility. No candidate disappears merely because it has little MAIN exposure, low stakes, comedy, a seasonal premise, a private focus, an unmodeled status or no operational model.

Eligibility means enough source-grounded material exists for a distinct sustained argument at the declared scope. Counts and metadata prompt inquiry; they do not supply that argument. A missing private pool does not automatically disqualify an actor whose public narrative is substantial. A single written object does not automatically justify a full monograph. Sparse or uncertain identities may still matter in a bounded role, relationship or institutional account.

## 4. Package acceptance

Every required package must have its own canonical path, exact identity/continuity scope, source routes and completion criteria. The audit freezes the package set only after the full candidate census is adjudicated.

For a character monograph, architecture §7.1 requires a core thesis, longitudinal arc, public/private self, school/club role, ordinary life, crisis behavior, Sensei relationship, major peers, language/voice, competing readings and evidence routes. Address absent or uncertain dimensions honestly; do not manufacture an arc, crisis, inner motive, private source or performed voice to fill a heading. A mature argument must distinguish testimony from shown action, explanation from justification, local sequence from global chronology and changed state from a newly sampled context.

Directed relationship packages require narrative significance, recipient-specific conditions, ordinary/crisis contrasts, asymmetries, conflicts, repair and remaining limits where evidenced. Co-occurrence is insufficient. Institutional packages distinguish mythology and stated mandate from actual governance, resources, work, dissent, legitimacy and observed outcomes. Profiles and club metadata cannot replace stories.

Quiet pleasure, wanted company, work, craft, play, rest, embarrassment, refusals and failed attempts have intrinsic literary value. They are required controls on crisis-centered interpretations. Sensei alternatives remain alternatives; private knowledge is not transferred to peers without evidence. Written register remains separate from performed voice. Operational reconstruction readiness remains separate from literary acceptance.

Semantic acceptance requires full received arguments, consequential evidence checks, serious competing readings, closure or explicit legitimate bounds on mandatory debts, and consistency with existing accepted state. A checksum, heading count, repository test or published filename cannot independently certify literary completion.

## 5. Progress and the four merges

**Progress denominator: NOT YET FROZEN. No quarter has been reached.** Candidate inventory and execution scaffolding do not count as completed literary packages.

After census adjudication, let `N` be the fixed number of required character, relationship and institutional packages. Each package counts once when its declared responsibility has passed semantic acceptance and its complete work is persisted on the series branch. Track drafting, acceptance, source publication and main integration separately. Package rows cannot be marked complete merely because supporting sources have been read.

| Milestone | Completed required packages | Required integration result |
|---|---:|---|
| 25% | `ceil(N / 4)` | First quarter's exact final source head audited, merged and post-merge audited |
| 50% | `ceil(N / 2)` | Second quarter's cumulative work integrated and post-merge audited |
| 75% | `ceil(3N / 4)` | Third quarter's cumulative work integrated and post-merge audited |
| 100% | `N` | All eligible-cast packages accepted; no pending census/required package debt; final convergence and integration verified |

Every quarter should preserve the architecture's structural variety and justified dependencies. A major character's difficulty is not a reason to exclude it or postpone its obligations indefinitely. Do not count an audit, manifest, index, directory or duplicated summary as a substitute for a character/relationship/institution argument.

If evidence changes membership, record the old and new package sets, reason, affected claims and revised thresholds. Do not reduce the denominator to erase unfinished eligible work or retrospectively announce a milestone that was never integrated. Legitimate deferrals must remain recoverable and must not conceal a mandatory source debt.

The current user instruction supplies merge authorization for these four milestones, superseding older merge reservations for this Phase 3 work. Ordinary source publication before a milestone may preserve completed work, but must use a draft PR or the governed nightly hold so it cannot be integrated early by the scheduler. Finish the complete source-audit/housekeeping/final-head sequence before the next source publication. Each milestone additionally requires a protected owner-authored PR merge and the explicit successful audit of the actual integration SHA. No force push, history rewrite, direct main push, security bypass or character/housekeeping ownership transfer is authorized.
