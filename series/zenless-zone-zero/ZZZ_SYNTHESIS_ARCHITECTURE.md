# Zenless Zone Zero — synthesis architecture

## 1. Scope, design and limits

This `INITIAL` design supports a versioned game corpus while acknowledging that only narrow derivative-package metadata is currently observed. It adopts the sixteen duties of the [architecture template](../../governance/analytical-methods/GENERIC_MULTI_DOCUMENT_SYNTHESIS_ARCHITECTURE_TEMPLATE.md). No full-game reading, frozen release, character dossier or model exists. Canonical authority concerns the current bootstrap design, never an asserted literary conclusion or run approval.

Graph reachability, mixed-speaker attribution and unlock-conditioned trust state are the distinctive day-one burdens. Separate technical partner/contact identities from analytical persons; inspect the source join and preserve unresolved candidates. An unbound fragment cannot become a scene just to supply context to a model. The current target selection does not imply corpus-wide relevance screening. Once a native story foundation is available, independently account for ordinary-life trust/message material without letting its abundance replace the main narrative. Frame and role identity require adjudication. The technical label GalGame establishes no nested frame, performance role, continuity or biography. Apply nested-frame rules only if directly inspected evidence establishes such a frame.

## 4. State, specialists and dependency order

Publication/release, depicted time, player disclosure, character knowledge and unlock order remain independent axes. Preserve old state IDs after change, and independent horizons for continuities/eras. A single person can have different relationship, knowledge and operational-role states without a psychological change. Branch possibilities and nested-role biographies do not silently enter mainline biography. Cross-game references have no shared-canon authority without independently admitted evidence and an explicit comparative scope.

Conditional specialist: **Graph-conditioned social interaction and nested frame attribution**. Trigger: Resolved narrative evidence establishes recurring differences among trust/unlock/choice states or nested roles that require an independent interpretive argument. It draws on full readings, the Identity crosswalk and State/Claims records. Its job is one sustained argument, not duplicating all evidence tables. No specialist file exists yet. Other specialists require the same proportionality test: recurrence, independent accumulation, later interpretive consequence, no adequate existing home and retrieval need.

Production order: verified source lock and gap resolution → explicit source/run admission → whole causal-block readings with ledger transactions → real boundary checkpoints → longitudinal and identity reconciliation → role-gap/readiness review → necessary character/relationship/specialist studies → convergence → integrated scope synthesis → final validation → release/freeze. Reconstruction evidence is captured throughout; model creation and independent evaluation have separate downstream gates. A monograph never certifies a model.

Analyst retrieval starts with the current entrypoint/source horizons and relevant full readings; a future reader guide starts from accepted synthesis and is written last. A synopsis remains navigation, never the only input to serious synthesis.

## 5. Distinct completion gates

| Gate | Acceptance evidence |
|---|---|
| Bootstrap | Current method/architecture and five required homes exist, source uncertainty remains explicit, lock closed |
| Source/run admission | Native identity and transform lineage verified, exact unit membership and all branch/channel gaps accounted for, explicit bounded authorization recorded |
| Block coverage | Complete admitted pages/nodes/choices/context read with full interpretation and all state/claim/coverage updates accepted |
| Longitudinal reconciliation | Source, identity, state, claims, form and reconstruction evidence routes agree; contradictions and stale claims have dispositions |
| Character/specialist readiness | Role-gap review accounts for peripheral perspectives, ordinary-life contexts, counterpart directions and missing channels; independent questions justified |
| Specialist convergence | Required studies complete and mutually reconciled; an explicit evidence-backed no-independent-study decision is allowed when direct synthesis can discharge the responsibility |
| Integrated-synthesis readiness | Exact input lock/horizons frozen; no omitted role or source-earned dimension; unresolved alternatives visible; full readings available |
| Final validation | Independent return to decisive sources; counterreading, attribution, state-contamination and deterministic retrieval tests; bounded defects repaired or stated as limitations |
| Release/freeze | Exact source/analysis scope and artifact inventory, review outcome, authority transitions, remaining gaps and next operation recorded; frozen bytes preserved |
| Reconstruction assessment | Separate evidence/model/held-out requirements met within a named state; evaluator alone assigns capability, not literary completion |

No gate implies the next. A pipeline exit, nonzero line count, source update or final unit reached is not analytical completion.

## 6. Revision, intake and freezing

Source changes append a new lock alias/version and an added/removed/changed identity crosswalk before locator movement. Relevance routing records which scopes a release concerns; impact triage uses `DEFERRED_PENDING_FOUNDATION` until a mature baseline exists, then `I0 RECORD_ONLY`, `I1 CHARACTERIZATION_INCREMENT`, `I2 INTERPRETIVE_REFINEMENT`, `I3 STATE_CHANGING`. I2/I3 obligations must be closed before affected claims advance their validated-through boundary. Retest all affected open/conflicting claims on substantial story additions; source-current never silently advances analysis-current or reconstruction-current.

Patch correction, rerun, removal and retcon remain separate events. Reuse without change adds no corroboration. Historical states remain valid for their original period. Mutable pointers update only after append-only history; frozen readings/checkpoints receive errata or superseding generations with reciprocal authority metadata. Release freshness is per scope, not one universal latest label.

An architectural amendment records motivating evidence, changed responsibility, dependency effects, source/ledger backfill and review. Move `INITIAL`→`EVOLVING` only through actual reviewed use. Stabilization or freeze reflects a real corpus milestone, not merely publication of these files.
